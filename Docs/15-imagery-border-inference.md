# Image-derived border estimates

The border pass targets every mapped layout without the existing supplemental inner/outer features. Existing borders are preserved. The first audit identified 495 mapped layouts across 320 circuits, plus 11 layouts with no mapped route.

Run the shared batch:

```sh
npm run border:infer -- --all --licensed-imagery --write
npm run model:prepare -- --bordered
npm run validate:border-inference
npm run build
```

`--licensed-imagery` enables the MapTiler source only when the operator has a separate agreement permitting automated extraction, working caches and redistribution of derived coordinates. Without that flag, only registered reusable sources are used. The server-only `MAPTILER_EXTRACTION_API_KEY` is preferred for acquisition; otherwise the configured `VITE_MAPTILER_API_KEY` is used. Both can come from the environment or ignored local configuration. The server-only key is never bundled in the frontend. Never put a key or a private agreement into a GeoJSON file.

`--track <id>` limits acquisition to one venue. `--refresh` replaces only this tool's unreviewed estimates after a new candidate validates. Failed refreshes retain the existing borders/model and record the failed attempt. A trace hash detects stale estimates. Government exports are cached by request hash. Licensed satellite tiles are cached by XYZ coordinate and only the road search corridor is acquired, so nearby layouts share downloads; at most three venues acquire imagery concurrently. The report is resumable and lists source/geometry gaps explicitly. Image requests time out and retry once. HTTP 429 responses persist the provider retry time and stop further requests during that window. `--retry-failed` retries only acquisition/quota failures and preserves the other report rows. Raster caches and inspection sheets stay in ignored `.local/border-inference/`.

The same GeoJSON contains the two proposed border features and `metadata.borderInference`. This records the method, unreviewed estimated status, source URL and public reuse evidence or a source-specific agreement reference, attribution/licence, retrieval time, raster SHA-256, exact Web Mercator extent, image dimensions, ground pixel size and image-evidence metrics. Licensed sources also store the provider, tile zoom and bounds, with no credentials. The runtime assembles parent tiles into a cropped texture of at most 2048 pixels per side. This preserves the saved ground extent while limiting mobile GPU memory. It contains neither raster bytes nor 3D objects. One shared `data/border-inference-coverage.json` records the remaining work; there are no per-layout processing files.

The detector samples RGB image cross-sections along the existing trace, scores visible transitions after a consistent road interior and selects continuous edges. It supplies no preferred road width. Ambiguous geometry, self-crossings, broad junctions, absent coverage, coarse pixels and weak image evidence are rejected. Synthetic imagery tests check that detected widths change with the image, and that a featureless image produces no borders. Visual checks exposed runoff-edge confusion in the first scoring rule; the second version increases the road-interior penalty. Image evidence scores remain **uncalibrated**, not probabilities of positional accuracy.

Accepted outputs are **unreviewed estimates**. Shadows, vegetation, paint, gravel, aprons, historical layouts and image age can still move a detected boundary. Fine road-edge accuracy and curb placement need manual review or survey data. The UI labels estimated borders and retains the imagery credit. Derived curbs remain illustrative. A 3D model does not make the underlying borders verified.

Open routes use `edgeConvention: left-right-along-trace`: the existing `inner` feature stores the left edge and `outer` stores the right edge, in trace order. The UI labels these left/right. Their endpoints remain separate and the browser creates a ribbon between corresponding stations. Accepted paired open routes receive `kind: run` models with a standing start, clamped monotone elevation and separate start/finish endpoints. Playback and recording stop at the finish; finish speed is unconstrained and no stopping zone is simulated. Road meshes, camera sampling and aerial outlines do not create a return segment. Branch networks need component topology and driving choices before extraction. Unmapped layouts need independent course identification before boundary extraction. The licensed source supplies global coverage where available; Sentinel imagery at 10 m does not resolve typical road edges.

## Reusable sources

- USGS/USDA NAIP imagery: public-domain orthophotos, with [USGS source and accuracy information](https://www.usgs.gov/centers/eros/science/usgs-eros-archive-aerial-photography-national-agriculture-imagery-program-naip).
- French IGN BD ORTHO: [Licence Ouverte 2.0 dataset](https://www.data.gouv.fr/datasets/bd-ortho-r), served by the Géoplateforme WMS.
- Spanish IGN PNOA: [CC BY 4.0 reuse conditions](https://www.ign.es/resources/licencia/Condiciones_licenciaUso_IGN_eng.pdf), with producer and derivative-work attribution.
- Existing pinned high-resolution venue imagery retains its registered source, licence and reuse evidence.

MapTiler extraction is enabled under an operator-confirmed separate imagery agreement. Its private text is held outside the repository. The derived features use `LicenseRef-MapTiler-Derived-Borders` and `rightsBasis: source-specific-agreement`; this is not an open-imagery licence or a claim that the agreement was independently reviewed. The [standard Cloud terms](https://www.maptiler.com/terms/cloud/) alone do not authorize tracing, extraction, caching or bulk downloads. Esri [World Imagery feature-extraction guidance](https://www.esri.com/arcgis-blog/products/arcgis-living-atlas/imagery/learn-to-use-ai-to-extract-information-from-world-imagery) restricts derived outputs to noncommercial use within ArcGIS. Those display services do not establish permission to redistribute inferred borders in this public dataset. Government imagery is preferred where supported. The licensed source is tried when other coverage or its image evidence fails. Existing successful estimates are cached and preserved.

## Offset source traces

`--appearance` opts into `rgb-road-appearance-v3`. It estimates the dominant road appearance near the trace and searches signed edge offsets from -10 to 25 m. This can recover pavement boundaries when part of a source trace lies on or outside the road. Width, contrast, continuity and crossing checks still apply. Proposals can follow aprons, vegetation or obsolete alignments and need image review before acceptance. A featureless image is rejected.

`--local-appearance` opts into `rgb-road-local-appearance-v4` for lighting changes that defeat a single road colour. It selects neutral pixels within 15 m of each trace station, takes their median colour, and filters that reference across neighbouring stations. The signed search range, edge evidence, width and crossing gates are unchanged. It can still mistake aprons, shoulders, buildings or bare ground for road, so a passing proposal requires image inspection. Three proposals have been screened and saved with pinned imagery using this method: Clastres, Snetterton 100 and Streets of Willow. The original trace and timing features remain unchanged. Existing estimates are not refreshed automatically.

For these appearance methods, `model3d.pathMethod: paired-border-midpoints` reconstructs the driving path from corresponding edge stations. No extra centerline or mesh is stored. The original trace and timing features remain intact. Distances follow the derived midpoint path and remain estimates. Existing models keep their original path method.

`--track <id> --layout <id>` processes a single layout and preserves the other coverage report rows. `--cached-image <image-sidecar.json>` pins a previously acquired raster and its validated metadata, rechecks the raster hash and avoids fetching a new crop. Source-specific images still require `--licensed-imagery`; a cached-only run needs no API credential. The extractor checks that the chosen frame covers its search corridor. Cached attribution can also be reused while a provider metadata request is quota-blocked.

For individually checked layouts with independently sampled closed borders, `model:prepare -- --track <id> --layout <id> --boundary-path` opts into `boundary-normal-midpoints-v1`. The browser samples the inner boundary, casts outward normals to the outer boundary and takes measured midpoints. Ring crossings, touching rings, unsupported widths and any unresolved runtime cross-section are rejected. The reconstructed driving path must remain inside the saved road surface. Original boundary vertices, trace and timing are preserved. No second centerline is stored. This mode is enabled for Mase and ICAR Mirabel after imagery inspection; the GeoJSON records the inspected image hash, retrieval date and source URL. Regeneration preserves that evidence and the pinned imagery reference. It is not enabled automatically for other alignment failures, which can represent different branches or historical configurations.

## Measured image corrections

A local-appearance proposal can be corrected with `--edge-refinement <anchors.json>` together with one `--track`, `--layout`, `--cached-image` and `--local-appearance`. The authoring input is not a new public track file. Its recipe is saved as `metadata.borderInference.refinement` in the same GeoJSON, alongside the final edge coordinates and compact model. Browser reconstruction needs no authoring input, mesh or stored video.

`cross-section-image-anchors-v1` records the pinned image hash, automatic seed-border hash, final-border hash, corrected edge, station indices and geographic anchor coordinates. Anchors explicitly distinguish `image-measured` positions from `preserved-seed` endpoints. Inside each corrected interval, measured offsets are interpolated in the original trace cross-section frames; the original trace and all edge vertices outside the interval remain intact. This uses variable image-derived positions rather than a nominal road-width fallback. Missing coverage, stale hashes, overlapping/unordered anchors, unsupported widths, contradictory closure anchors, crossing/touching or unnested rings and corrections that move more than 1.5 m along the driving order are rejected. Build validation checks the final coordinate hash and saved anchor positions.

Open-route corrections explicitly use the left/right convention and clamp cross-section sampling at the endpoints. They retain distinct start and finish vertices, check left/right order and test every nonadjacent segment for crossing or touching, including the first and last segments. Curborough corrects four left-edge positions at the start straight with one preserved join point. Access-junction transitions and other automatic sections remain unverified. Loton adds an unrefined image-derived estimate. Both store terrain and a standing-start run recipe in their existing GeoJSON.

Refreshing the same pinned image replays the stored recipe without a separate anchor file. Extraction evidence scores describe the original automatic proposal, not confidence in the corrected geometry. A changed source image or seed requires a new correction recipe; failed refreshes preserve existing data.

Arizona Motorsports Park uses 22 image-measured positions and 12 preserved seed endpoints across six intervals to correct asphalt-seam detections. Its junction transition remains provisional and other sections retain automatic estimates. Its borders remain unverified, and its curbs remain illustrative. The UI labels layouts that include measured corrections without presenting them as surveyed or fully reviewed.

M-Sport’s inner variant reuses the same correction workflow. Five image-measured positions correct the building-side edge where the seed followed the far side of a grass strip; two seed endpoints preserve the joins. Wide test pads and junction transitions elsewhere remain provisional automatic surface limits. The longer variant remains unresolved because its northern circle and triangle joins produce crossing boundaries. Diagnostic proposals are not eligible public borders.

## Networks with existing driving routes

`npm run compose:networks -- --write` matches each network trace path exactly to an existing playable layout at the same venue. A network is composed only when every component matches. Declared component IDs in its source recipe take precedence over geometry-equivalent aliases. Without declared IDs, a match must be unambiguous. Names, timing and playback metadata come from the intended component, and build validation checks this identity. It copies the existing borders and compact playback recipes without running imagery extraction again. The network GeoJSON retains each component's name, original metadata, timing, licences, imagery evidence and a hash of the normalized source layout under `metadata.borderComposition`. One terrain raster is shared across the components; there are no meshes, videos or extra per-network files. A downloaded network GeoJSON can reconstruct every included route without fetching its sibling files.

The UI keeps the network overview and offers a named driving-route selector for playback and recording. Open components remain open, with distinct endpoints. Mixed feature licences are preserved per path, rather than replaced by the network's trace licence. `npm run validate:networks` verifies both the source layout hash and the exact reconstructed component. Catalogue regeneration preserves the composition. Updating a component requires recomposing its network before the build passes.

## Coverage

A new acquisition and local-appearance pass assessed all 27 remaining open non-network routes. Twelve proposals passed automatic gates; native-image screening accepted Curborough and Loton, and held ten proposals because of shadows, canopy, adjoining paving or ambiguous drag-strip barriers. Fifteen failed evidence or geometry gates. The ledger now records these specific reasons rather than the obsolete generic open-route limitation.

The batch assessed all 495 originally unbordered mapped layouts, plus 11 layouts without mapped routes. It has saved 204 unverified estimates after automatic geometry/evidence checks and pinned-image screening. Visual screening does not establish surveyed accuracy or validate actual curb locations. Six open-route estimates support point-to-point playback and recording. Thirty-five networks now compose 104 existing driving routes. Fifteen gain borders from their components; twenty retain their original border features exactly. The remaining 276 mapped layouts comprise 246 needing image/geometry review and 30 needing route interpretation. The prior provider quota block has cleared and all 92 acquisition failures were reassessed. These gaps remain explicit. Surface-only routes still require playback work where a driving order can be established.

Together with existing models this gives 1,101 3D layouts across 627 circuits: 1,041 playable laps, 6 point-to-point runs, 35 networks with driving-route choices and 19 surface-only views. All 882 original border sets are preserved. The initial pass's estimates also remain unchanged.

For government export/WMS and licensed tiled sources, the 3D backdrop uses the same georeferenced imagery reference as the extraction. Pinned sources retain a separate display backdrop and source evidence in the GeoJSON. External imagery availability and quotas can affect the backdrop; saved road geometry and lap playback remain usable.

Castle Combe Western Sprint remains surface-only. Its saved source route includes the pit-exit start and repeated circuit sections over one and three-quarter laps. The existing closed borders omit the pit-exit road. Recentring that start onto the main straight would change the route, so those borders cannot supply the whole run. The entry needs its own measured edges before playback can be enabled. The source trace and its draft timing extent remain intact.

## Large imagery extents

Licensed acquisition keeps its native target resolution when a bounding rectangle exceeds 64 megapixels. It fetches only the trace corridor and reads it through a tile-backed virtual raster with an eight-tile decode cache. No dense image of the full rectangle is allocated. Missing pixels remain missing; they are never filled with an assumed road colour. Smaller extents keep their existing PNG workflow.

For tiled evidence, `metadata.borderInference.imagery.encoding` is `xyz-jpeg-manifest-v1`. Width and height describe the virtual pixel grid. Its `sha256` hashes the canonical JSON manifest with schema version, zoom, tile bounds and the sorted list of tile coordinates and JPEG SHA-256 values. The ignored local manifest and tile files are checked when reopening pinned evidence, including tiles outside the detector's sampled pixels. No tile bytes or manifests are added to the public GeoJSON. The saved road coordinates remain sufficient to rebuild the model. A separate preview PNG, limited to 2048 pixels per side, is for inspection and is never used for inference.

Pikes Peak acquisition now succeeds at about 0.46 m ground pixels over a 172-megapixel virtual extent using 140 corridor tiles. The extraction retained at most 8 MB of decoded pixels. Its first proposals are held because reviewed edges include dirt shoulders and vegetation; acquiring suitable imagery alone does not establish valid road limits.

## Unmapped course identity

A licensed high-resolution inspection on 6 November 2026 covered nine unmapped entries across seven areas: Arlington and its Practice entry, Elvington's northern return, Huangtupo, Lydden Hill Infield, both Kames timed runs, Thoresway and Detroit City Airport. The images have approximately 0.44–0.75 m ground pixels. Retrieval time does not establish capture time; these source references supply no capture date.

The shared [inspection record](../sources/research/licensed-unmapped-imagery-review.json) retains source licences, extents, dimensions, resolution, imagery hashes and specific findings. It also fingerprints the bounded current Arlington OSM check. Working rasters and inspection grids stay in the ignored cache. No course geometry was recovered in this inspection. Historical branch order, event connectors, timing conventions or temporary barrier placement remain unresolved. All eleven unmapped catalogue entries retain their status, including Rosario and Charlotte Short, whose earlier fine-image reviews already identified route-identity gaps. Public mapping notes and the shared coverage ledger record the specific outstanding evidence.
