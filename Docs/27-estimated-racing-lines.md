# Ideal line

Layouts with a calculated `ideal` GeoJSON feature have an **Ideal line** display toggle. It is off by default and works in Map, Satellite and 3D views. Downloading a layout includes its line. Source traces, timing and terrain grids are preserved. Border changes are limited to explicit, pinned input corrections described below, with their own source rights and refreshed models.

## Data

The optional feature uses `id: "ideal"`, `properties.role: "ideal"`, `estimated: true`, the method version, an edge margin in metres and the source border licence identifiers. A LineString represents a single corridor; MultiLineString represents independently calculated component corridors in a network. Network lines do not assert a unique racing order through junctions. When every exact embedded source component already has a validated ideal line, the generator can reuse those paths in component order, preserving open endpoints and lap closures. It rejects missing lines or changed source components. The composed feature records the minimum edge margin guaranteed by all its components. No meshes or duplicated border arrays are added.

The line is derived from the saved boundaries, so their separate licences continue to apply. It is not relabelled as an OSM source trace. Existing route/model fingerprints exclude this display-only derived feature; the crossing audit still fingerprints complete layout files.

## Calculation

`npm run ideal:generate` runs four independent numeric worker processes and writes both the GeoJSON features and `data/ideal-lines-coverage.json`. Detailed intermediate logs are in `.local/ideal-generation/`.

The first pass constructs a boundary-normal corridor and samples approximately every 9 m. A finer direct-boundary pass attempts tight or irregular corners. Short corner-cutting chords are repaired only when the complete replacement fits the same source footprint with the required clearance. Local backtracking loops are removed while preserving the cycle around the source island. The line solver keeps its input footprint fixed; source-boundary corrections follow the separate review procedure below. A nearest-visible-edge pass handles valid rings whose normal rays hit a distant branch. It excludes reference samples that cannot accommodate the preset only when the final validated cycle still wraps the unchanged source island. Bounded grid routing can follow multi-corner detours without crossing or removing dividers. Final passes use the existing ordered road reconstruction, including explicitly grade-separated routes. Layouts that fail topology or width checks remain unavailable and are recorded in the coverage file rather than receiving an invented path.

The fixed illustrative dry-condition vehicle preset is in `src/ideal-line-model.ts`: 1,350 kg, 410 kW, 2.05 m width, 285 km/h speed ceiling, 1.55 g mechanical lateral grip, an assumed additional 0.85 g at 200 km/h, and a 3 g lateral ceiling. These are assumptions, not measured tyre/aero data.

An existing shared-ground reconstruction can also supply the corridor. These lines record `boundaryModel: "shared-ground-v1"` and include the reconstruction imagery licence in `borderLicenses`. The optimizer retains every source station in order and bounds lateral movement by the complete adjacent source segments' clearance, preserving the source route through its grass islands. Every resulting segment is checked continuously against the saved reconstructed footprint. No source boundary or reconstruction pin is changed. Composed networks do not currently reuse this boundary-model-specific feature.

For projected source crossings with unpaired closed borders, a source-order pass aligns both complete edge curves in source travel order. It inserts samples on original segments, retains every original vertex and uses monotonic dynamic alignment within a 120 m station band. The alignment rejects widths below the vehicle envelope, widths above 45 m, folded cells and intersecting cells. Each ideal segment must clear a simple local strip extending 20 m in both travel directions, continuously along the whole segment. This avoids treating the other visit to a projected crossing as an obstacle. The final line must preserve the source crossings and their order, within 45 m in position and 120 m in relative route station. These lines record `boundaryModel: "ordered-border-ribbon-v1"`. They are two-dimensional estimates with a flat optimization profile; they do not establish bridge elevation, vertical clearance or a calibrated lap time. Original borders, source route and elevation models remain unchanged.

A final planar recovery handles simple nested corridors where the complete vehicle fits with less than 0.1 m additional margin. It records `boundaryModel: "continuous-planar-v1"` and an explicit 0.01 m edge margin. The 2.05 m vehicle width remains unchanged. The complete source annulus is retained; local reference-point refinements move at most 2 m and are accepted only through whole-segment clearance checks. Lateral optimizer bounds use both adjacent complete segments' clearance. Every final segment must continuously clear half the vehicle width plus the recorded margin and a 0.002 m numerical reserve. The simple final cycle must enclose every original inner-edge vertex and no outer-edge vertex. The smaller margin describes the numerical geometry, not measured clearance on the real road.

Bounded coordinate descent minimizes discrete integrated curvature squared. Smooth local lateral perturbations at 100, 60 and 35 m scales refine the path using a forward/backward power/braking speed model with combined grip. The speed refinement is checked with a more precise solve against its curvature seed. Subsequent footprint-containment repairs may increase distance or travel time; that seed comparison is not a claim about the final repaired line. This independent heuristic uses concepts from [TUM's trajectory project](https://github.com/TUMFTM/global_racetrajectory_optimization); it does not execute or vendor TUM's optimizer, and does not establish a global minimum-time solution.

Unambiguous source-boundary corridors are checked every metre against the saved road rings and nearest edges, allowing half the vehicle width plus the feature's edge margin. Most features retain 0.5 m extra clearance; the narrow recovery pass allows 0.1 m; the continuous planar pass records 0.01 m with the continuous checks described above. Local self-crossings in a saved border need not prevent a planar line: the nearest-edge pass retains every original segment as a clearance obstacle and uses its unchanged even-odd footprint. Its final simple cycle must enclose every inner-edge vertex and no outer-edge vertex, in addition to passing the footprint and width checks. A projected crossing that cannot satisfy that separation remains unavailable through this method. Explicit grade-separated source reconstructions use their ordered layer-specific ribbon bounds instead of treating another level's edges as obstacles. This is a sampled width-envelope check, not full-body swept-volume qualification.

Closed boundary reconstructions use flat banking and elevation; recovery from saved road models can include their estimated longitudinal slope. Banking, kerbs, vertical compression, transient handling, surface variation and telemetry calibration remain absent. The display name “Ideal line” describes an estimated racing-line overlay, not a certified driving target or a prediction of real lap records.

## Reviewed input corrections

Botniaring Full's original inner border cut across open pavement on the western straight; its outer border also contained a centimetre-scale self-crossing. The licensed approximately 0.55 m ground-pixel image, complete candidate overlay and affected straight were reviewed. Its source route is exactly the same 124-node closed cycle as the already image-estimated `main` layout, starting four nodes later. The replacement reruns the appearance estimator in the unchanged target route's own order using the same pinned image. It retains estimated status; shared-paving limits and pixel-scale uncertainty remain unresolved.

[The review pin](../sources/research/botniaring-border-reestimate.json) records the original pair hash, source layout/trace/border hashes, image hash, expected output hash and exact cycle correspondence. The same proof is embedded under `borderInference.supersedes.sameCycleReview`. Changed nodes, a different route order, altered source borders, different imagery or a changed candidate stop replacement. The target's trace, timing and terrain remain unchanged; its boundary features now carry the image-provider rights, and its road model is refreshed. Raw working imagery is excluded from the repository and public build.

Pittsburgh South's original outer border contained an inward spur across the paved straight beside the paddock. A complete sparse reconstruction uses 126 independently located asphalt-edge observations plus two closure anchors on the pinned public-domain NAIP image (0.75 m ground-pixel sampling). Cross-section offsets were read to 0.5 m, excluding curbs; this rounding does not establish measurement accuracy. Intervals between observations and access openings remain interpolated estimates. The embedded measurement recipe and superseded border hash reproduce and identify the correction. The complete overlay was reviewed against the native image. Source trace, timing and terrain remain unchanged; the road model is refreshed. The source layout identity remains draft.

Autobahn North's original outer border also contained a spur across the pit straight. Its replacement uses 157 sparse asphalt-edge observations plus two closure anchors on the pinned licensed image (approximately 0.45 m ground-pixel sampling). Readings are rounded to 0.5 m and exclude curbs. Two access openings and three more heavily shadowed sections have no claimed observation; those limits interpolate between adjoining anchors. Shadow, paint and pixel interpretation remain sources of uncertainty. The complete overlay was reviewed. The embedded recipe and original border hash make the correction reproducible; trace, timing and terrain are preserved, with the road model refreshed.

NCM's Corvette loop had borders that skipped the retained source route's bend near the southern pit entrance, together with an outer-border spur across the straight. Its complete replacement has 213 sparse observations plus two closure anchors on the pinned licensed image (approximately 0.48 m ground-pixel sampling). Selected limits follow visible paint, the asphalt side of curbs, asphalt transitions and grass, excluding adjoining runoff and pit access. Readings are rounded to 0.5 m; texture interpretation and image resolution remain uncertain. One shadowed section and four junction openings have no claimed anchor. Those gaps and all other unmeasured intervals interpolate. The complete overlay was reviewed against the image. The embedded recipe, original border hash, preserved trace/timing/terrain and refreshed model follow the same correction workflow. Layout identity remains draft.

Road Atlanta's full and SRO Practice routes each had an outer-border spur across the paved pit straight. The full route uses 266 sparse observations plus two closure anchors on pinned public-domain NAIP imagery (approximately 0.75 m ground-pixel sampling). SRO reuses 254 supported observations on the same road and adds 12 independent observations on its differing source section, plus closure. Readings are rounded to 0.5 m; unobserved openings, obscuring shadows and other intervals interpolate. Selected limits exclude adjoining runoff and pit access. Both complete overlays were reviewed; provisional identity and historical alignment are unchanged. [The review record](../sources/research/road-atlanta-border-review.json) pins the image, correction hashes and dependent network refresh.

The combined layout propagates these two corrections from its exact embedded old components while retaining its Short component unchanged. `compose:networks -- --write --track <id> --layout <id> --replace-legacy-layout-hash <hash>` is restricted to one pinned original network. It checks each old embedded source hash; a changed component must have complete measurements pinned to that exact old border pair and preserve its trace, timing, metadata and terrain. Default composition still refuses a legacy-border mismatch. The network's source trace, timing and terrain remain unchanged. Neither Short nor Combo gains an ideal line: the pinned image shows grass along part of Short's provisional connector, so that branch needs matching historical limits or route review.

## Validation

```sh
npm run typecheck
npm run lint
npm test
npm run build
RACETRACK_TEST_URL=http://127.0.0.1:5194 npx playwright test tests/ideal-lines.spec.ts
```

Tests cover optional schema and licence scope, canonical serialization/regeneration, unchanged model fingerprints, the speed envelope, opt-in display, embedded download, 2D/3D toggle behavior, mobile overflow and stale-line clearing on layout changes. Catalogue generation preserves the derived feature while rebuilding the independently sourced geometry.
