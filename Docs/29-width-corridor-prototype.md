# Width-only corridor prototype: Spa, Suzuka and Nürburgring

This note describes the original three-venue prototype. The subsequent [database-wide width rollout](31-width-corridor-rollout.md) supersedes its coverage scope. Each `track.json` layout entry stores `roadWidthM`, rounded to the nearest 0.5 m, and `roadWidthSource`. No inner, outer or ideal coordinates are stored in their layout GeoJSON files. The mapped source trace, timing markers and existing terrain/elevation/imagery data are retained. This initial scope has since expanded as described in the rollout note.

Widths are arithmetic means of the existing cross-section widths weighted by road distance: `sum((left + right) * ds) / sum(ds)`. The source records the unrounded value, sample count, interpolated source-section count, length, source-border hash and applicable licences. This measures the previous estimated geometry, not a newly surveyed road width. Spa rounds to 10 m, Suzuka to 9.5 m, Nürburgring GP layouts to 13 m, Nordschleife variants to 9.5 m, NLS to 10 m and the 24-hour layout to 9.5 m.

The frontend uses a Web Worker to reconstruct a sampled, smoothed reference from the unchanged mapped trace, normal offsets at half the width, and an ideal line with a 0.1 m car-side margin. The earlier short local curvature pass has been replaced with a coupled iterative curvature QP and vehicle-model time refinement; see [the solver method and validation](30-browser-trajectory.md). The reference and output spacing is at most 1.5 m. Results are cached in the browser session by trace, width, geometry mode, elevation and source licences. Initial calculation time depends on route length and the optimization work; the UI remains responsive while the worker calculates.

Simple sharp offsets can fold over themselves. The derived reference locally rounds overly tight mapped kinks, with displacement capped at one half of the stored width (the later rollout limit), while leaving the stored original trace untouched. In this experiment the largest local adjustment was approximately 2.7 m at Nürburgring GP without the arena. Most layouts need no such adjustment. These are hypothetical constant-width corridors, not restored physical asphalt boundaries. The frontend labels them as estimates. Local widening, exact kerb positions, previous off-centre boundary corrections and actual road asymmetry are deliberately not encoded by a single width. Previously generated curb intervals are removed rather than presented at obsolete positions.

At Suzuka the existing bridge/elevation evidence is retained separately in the compact model. Its height anchors and upper/lower spans are remapped in source order to the new trace-reference grid; the crossing is not flattened or treated as a planar obstacle. These remain estimated heights and clearances. Route/timing coordinates and stored BTG timing endpoints are preserved.

Old imagery-derived borders, ideal lines and local Breidscheid/Karussell repair evidence are preserved in the authoring snapshot under `.local/width-prototype/before/`, the existing research evidence, and `.local/width-prototype/previous-inspection/`. They are not secretly used as fallback coordinates by the new frontend mode. The earlier Karussell review is labelled as archived. Inspect placement and its comparison image have since been removed from the application. Archived evidence is not used as the source of the newly rebuilt road edges.

The original measurement and three-venue migration scripts are archived locally; `scripts/migrate-width-corridors.ts` is the retained general migration tool. `trace-width-calculation.ts` is the pure worker calculation, and `trace-width-road.ts` builds the matching driving surface. The GeoJSON download is the compact source; the Track data link supplies the width needed to reconstruct it. Derived runtime GeoJSON objects are not written back to the database. Trace, width-source, and comparison-imagery rights continue to apply.

Focused checks cover all twelve compact files and reconstructed runtime layouts, trace identity, timing, constant-width construction, geometry topology safeguards, finite playback, and retained Suzuka bridge levels. This preview does not rerun the full imagery/database authoring validation or make a production rollout. Broader authoring-tool adoption is separate from this three-venue experiment.
